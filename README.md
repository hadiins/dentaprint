# دنتاپرینت — فروشگاه اختصاصی تجهیزات و مواد دندانسازی و دندانپزشکی

Next.js 15 (App Router) · React 19 · TypeScript · PostgreSQL · Prisma

> **استقرار روی سرور:** راهنمای کامل در [`DEPLOY.md`](DEPLOY.md) (Railway، لیارا، سرور مجازی با Docker).

## اجرای سریع (بدون پایگاه داده)

```bash
npm install
cp .env.example .env      # خط DATABASE_URL را فعلاً کامنت کنید تا حالت نمایشی فعال شود
npm run dev               # http://localhost:3000
npm test                  # تست‌های موتور قیمت‌گذاری
```

در این حالت محصولات از `src/lib/catalog.ts` خوانده می‌شوند و فرم همکاری فقط اعتبارسنجی می‌شود.

## اجرا با پایگاه داده

```bash
docker compose up -d      # PostgreSQL 16
npm run db:migrate        # ساخت جداول از prisma/schema.prisma
npm run db:seed           # سطوح همکاری، دسته‌ها و محصولات نمونه
npm run dev
```

## دسته‌بندی محصولات

| گروه | دسته‌ها |
|---|---|
| 🖨️ چاپ سه‌بعدی | رزین مدل، رزین کلینیکی، پرینتر دندانی، شستشو و کیورینگ |
| 🦷 پروتز و دندان مصنوعی | دندان مصنوعی، آکریل و مواد پروتز (آکریل حرارتی/سرد، موم، گچ)، تجهیزات پروتز (کورهٔ پرسلن، دستگاه پخت آکریل، پرس، فلاسک) |
| ✨ ترمیمی و پرکردن | کامپوزیت و مواد پرکردن (نانوهیبرید، فلوابل، بالک‌فیل، گلاس آینومر)، باندینگ/اچ/لاینر، تجهیزات ترمیمی (لایت کیور، کپسول‌میکسر، گرم‌کن) |

نوع محصول: رزین، **مواد اولیه**، تجهیزات، مواد مصرفی. هر محصول می‌تواند **کد IRC** (ادارهٔ کل تجهیزات پزشکی) داشته باشد که در صفحهٔ محصول نمایش داده می‌شود.
گروه‌ها و دسته‌ها در `src/lib/catalog-meta.ts` تعریف شده‌اند.

## رنگ‌بندی، فرم و تنوع محصول

- هر محصول حداکثر **۲ گزینه** دارد (مثلاً «رنگ» و «فرم» یا «رنگ» و «فک»). هر ترکیب = یک تنوع با **کد کالا، موجودی و قیمت اختیاری جداگانه**.
- صفحهٔ محصول: انتخاب با دکمه؛ ترکیب‌های ناموجود خط‌خورده و غیرفعال‌اند؛ تا انتخاب کامل نشود افزودن به سبد ممکن نیست.
- **همکاران:** حداقل تعداد و تخفیف پلکانی روی مجموع همهٔ رنگ‌ها/فرم‌های یک محصول حساب می‌شود (مثلاً ۳ عدد A1 + ۲ عدد A2 = ۵ عدد).
- قیمت جداگانهٔ تنوع (مثلاً رنگ Incisal گران‌تر) جای قیمت محصول را می‌گیرد و تخفیف درصدی سطح روی آن اعمال می‌شود.
- سرور در ثبت سفارش انتخاب، وجود و موجودی تنوع را دوباره بررسی می‌کند. **بعد از پرداخت موفق، موجودی محصول و تنوع کم می‌شود.**
- پنل مدیریت ← محصول: الگوهای آماده (رنگ‌های VITA، رنگ کامپوزیت، فرم دندان)، جدول زندهٔ ترکیب‌ها برای موجودی، قیمت و فعال/غیرفعال. با تغییر گزینه‌ها، اطلاعات ترکیب‌های قبلی حفظ می‌شود.
- در سفارش، اقلام با برچسب خوانا ذخیره می‌شوند (مثلاً «رنگ: A2 · فرم: S (مربعی)») و کد کالای همان تنوع.

## عکس محصولات

- **پنل ← ویرایش محصول:** بارگذاری چند عکس با کشیدن و رها کردن (تا ۱۲ عکس، هر کدام تا ۸ مگابایت)، تعیین عکس اصلی، جابه‌جایی، متن جایگزین (سئو)، حذف.
- **عکس اختصاصی هر رنگ:** هر عکس را می‌توان به یک مقدار گزینهٔ اول (مثلاً رنگ A2) نسبت داد. در فروشگاه با انتخاب رنگ، عکس همان رنگ اول نمایش داده می‌شود و عکس رنگ‌های دیگر پنهان می‌شود.
- **پردازش خودکار (sharp):** چرخش بر اساس EXIF، حذف متادیتا (از جمله مکان GPS)، کوچک‌سازی تا ۱۶۰۰ پیکسل و تبدیل به WebP. اندازه‌های واکنش‌گرا و AVIF را next/image هنگام نمایش می‌سازد.
- **امنیت:** نوع فایل از بایت‌های ابتدایی تشخیص داده می‌شود (نه پسوند)؛ SVG و GIF پذیرفته نمی‌شوند؛ نام فایل‌ها تصادفی است؛ مسیرها در برابر `../` محافظت شده‌اند؛ فقط مدیر می‌تواند بارگذاری کند.
- **ذخیره‌سازی قابل تعویض:** `MEDIA_STORAGE="local"` (پیش‌فرض، پوشهٔ `uploads` که باید در بکاپ باشد) یا `"s3"` برای آروان‌کلود/MinIO/لیارا.
- بدون عکس، همان آیکون قبلی نمایش داده می‌شود. عکس‌ها در صفحهٔ محصول، کارت‌ها، Open Graph (اشتراک‌گذاری) و اطلاعات ساختاریافتهٔ گوگل استفاده می‌شوند.
- اگر پشت Nginx هستید: `client_max_body_size 100m;`

## مدارک همکاران

- **همکار** (حساب کاربری ← «مدارک همکاری»): بارگذاری پروانه، کد اقتصادی، کارت ملی، عکس محل کار، نمونه کار و سایر؛ PDF یا عکس تا ۱۰ مگابایت، حداکثر ۱۵ مدرک؛ مشاهدهٔ وضعیت و یادداشت کارشناس؛ حذف مدرک بررسی‌نشده.
- **مدیر** (پنل ← همکاران ← جزئیات): مشاهده/دانلود، تأیید یا رد (برای رد، نوشتن دلیل الزامی است)، پیامک نتیجه به همکار. تعداد مدارک در انتظار در داشبورد و فهرست همکاران دیده می‌شود.
- **خودکار:** تأیید پروانه یا کد اقتصادی ← سطح تأیید «تأیید با مدرک» و ارزیابی دوبارهٔ سطح همکاری (مثلاً باز شدن سطح طلایی). رد آخرین مدرک رسمی ← بازگشت به «تأیید پایه». تأیید پایهٔ همکاران بدون پروانه همچنان با تصمیم مدیر است.
- **حریم خصوصی و امنیت:**
  - ذخیره‌ساز **خصوصی و جدا** (`PRIVATE_UPLOAD_DIR` یا باکت خصوصی `S3_PRIVATE_BUCKET`)؛ هیچ آدرس عمومی ندارد. اگر پوشهٔ خصوصی داخل پوشهٔ عمومی تنظیم شود، برنامه اجرا نمی‌شود.
  - دسترسی فقط از `/api/documents/[id]` برای مدیر یا صاحب مدرک؛ برای بقیه ۴۰۴ (وجود فایل هم فاش نمی‌شود).
  - عکس‌ها دوباره کدگذاری می‌شوند (حذف GPS و محتوای پنهان)؛ PDF فقط به‌صورت دانلود و با هدر `sandbox` تحویل می‌شود؛ `no-store` برای جلوگیری از کش.
  - نام فایل‌ها تصادفی ۳۲ کاراکتری؛ نوع فایل از محتوا تشخیص داده می‌شود.
  - پوشهٔ `private-uploads` را در بکاپ رمزنگاری‌شده نگه دارید.

## فاکتور

- **صدور خودکار** بلافاصله بعد از پرداخت موفق؛ شمارهٔ ترتیبی سالانهٔ شمسی بدون شمارهٔ خالی یا تکراری (`1405-000001`)؛ هر سفارش فقط یک فاکتور (حتی با بازگشت هم‌زمان از درگاه).
- **نسخهٔ ثابت:** اطلاعات فروشنده، خریدار، اقلام (با رنگ/فرم) و مبالغ در لحظهٔ صدور ذخیره می‌شوند؛ تغییر قیمت یا اطلاعات فروشنده، فاکتورهای قبلی را تغییر نمی‌دهد.
- **دو نوع:** «فاکتور فروش» و «صورتحساب فروش کالا و خدمات» (رسمی) — در صفحهٔ پرداخت با زدن گزینهٔ «فاکتور رسمی» و وارد کردن نام حقوقی، کد اقتصادی (۱۲ یا ۱۴ رقم) و شناسهٔ ملی.
- **محتوا:** مشخصات فروشنده و خریدار، شرح کالا، کد کالا، تعداد، مبلغ واحد، تخفیف همکاری، ارزش افزوده (در صورت فعال بودن)، جمع کل، **مبلغ به حروف**، تاریخ شمسی (منطقهٔ زمانی تهران)، محل مهر و امضا.
- **ارزش افزوده قابل تنظیم** (پنل ← 🧾 فاکتور): غیرفعال (پیش‌فرض)، یا با نرخ دلخواه به‌صورت «شامل قیمت» یا «اضافه بر قیمت»؛ واحد ریال یا تومان. گرد کردن در سطح هر ردیف تا جمع ستون‌ها دقیق باشد. **نرخ و روش را با حسابدار تأیید کنید.**
- **دسترسی:** `/invoices/{شمارهٔ سفارش}` فقط برای صاحب سفارش و مدیر؛ لینک در حساب کاربری، صفحهٔ نتیجهٔ پرداخت و پنل سفارش‌ها.
- **PDF:** صفحه برای چاپ A4 طراحی شده؛ دکمهٔ «چاپ / ذخیره به‌صورت PDF» در مرورگر، PDF با حروف فارسی کاملاً درست می‌سازد. بدون پایگاه داده، «پیش‌نمایش» با واترمارک نمایش داده می‌شود.
- اطلاعات فروشنده: `config/seller.json` یا پایگاه داده (از پنل قابل ویرایش).

## پنل مدیریت (`/admin`)

ورود با شماره‌های `ADMIN_PHONES`. بخش‌ها (به‌جز «سطوح و قیمت») به پایگاه داده نیاز دارند.

| بخش | امکانات |
|---|---|
| 📊 داشبورد | درخواست‌های همکاری در انتظار، سفارش‌های آمادهٔ ارسال، فروش امروز، موجودی رو به اتمام |
| 📦 سفارش‌ها | فیلتر وضعیت و جستجو؛ جزئیات اقلام، آدرس و پرداخت‌ها؛ تغییر وضعیت فقط در مسیرهای مجاز؛ کد رهگیری الزامی برای «ارسال‌شده»؛ تاریخچه؛ پیامک به مشتری |
| 🤝 همکاران | فیلتر و جستجو؛ اطلاعات، خرید بازهٔ ارزیابی و فاصله تا سطح بعد؛ تأیید/رد/تعلیق، سطح تأیید (پایه یا با مدرک)، انتخاب و قفل سطح، یادداشت داخلی؛ پیامک به همکار |
| 🧪 محصولات | فهرست و جستجو؛ افزودن/ویرایش (قیمت، کف قیمت، سقف تخفیف همکار، حداقل تعداد همکار، قیمت دستی هر سطح، موجودی، مشخصات فنی، IRC)؛ فعال/غیرفعال |
| ⚙️ سطوح و قیمت | همان تنظیمات سطح‌بندی، پله‌ها و ارسال |

قوانین: سطح نیازمند مدرک فقط با «تأیید با مدرک» قابل انتخاب است؛ لغو یا مرجوعی سفارش، سطح همکار را دوباره ارزیابی می‌کند؛ تغییر هم‌زمان وضعیت توسط دو مدیر تشخیص داده می‌شود.

## ورود با کد پیامکی

- `/login`: شماره ← کد ۵ رقمی ← (کاربر جدید) نام. بعد از ورود به صفحهٔ قبلی برمی‌گردد.
- `/account`: سفارش‌ها، و برای همکاران: سطح فعلی، خرید بازهٔ ارزیابی، نوار پیشرفت و مبلغ باقی‌مانده تا سطح بعد.
- قیمت همکار **فقط** از حساب همکار تأییدشده خوانده می‌شود (سرور و مرورگر). ثبت سفارش و پرداخت نیاز به ورود دارد و هر کس فقط سفارش خودش را می‌تواند پرداخت کند.
- مدیرها: شماره‌های `ADMIN_PHONES` هنگام ورود نقش مدیر می‌گیرند و به `/admin/settings` دسترسی دارند.

**امنیت:** کد تصادفی رمزنگاری‌شده و فقط هش آن ذخیره می‌شود؛ اعتبار ۲ دقیقه؛ حداکثر ۵ تلاش؛ فاصلهٔ ارسال مجدد ۹۰ ثانیه؛ سقف ۵ پیامک در ساعت برای هر شماره و ۲۰ برای هر IP؛ کوکی `httpOnly` و `SameSite=Lax`؛ در پایگاه داده فقط هش توکن نشست ذخیره می‌شود.

**سرویس پیامک قابل تعویض** (مثل درگاه پرداخت): `SMS_PROVIDER="kavenegar"` یا `"smsir"`. برای سرویس دیگر از `src/lib/sms/providers/_template.ts` استفاده کنید و یک خط به `sms/registry.ts` اضافه کنید.
در توسعه (`SMS_PROVIDER="console"`) کد در ترمینال سرور چاپ می‌شود.

**تست همکار بدون پایگاه داده:** با شماره‌های `DEMO_PARTNERS` وارد شوید (مثلاً `09122222222` ← همکار نقره‌ای).

**ارتقای سطح:** بلافاصله بعد از هر پرداخت موفق، و روزانه با:
```bash
curl -H "Authorization: Bearer $CRON_SECRET" https://your-site.ir/api/cron/evaluate-tiers
```

## پرداخت — هر درگاهی قابل اتصال است

همهٔ درگاه‌ها یک قرارداد مشترک دارند (`src/lib/payments/types.ts`) و بقیهٔ سیستم به درگاه خاصی وابسته نیست.

| درگاه | فایل | تنظیم |
|---|---|---|
| آزمایشی (بدون پول واقعی) | `gateways/mock.ts` | `PAYMENT_GATEWAYS="mock"` |
| زرین‌پال | `gateways/zarinpal.ts` | `ZARINPAL_MERCHANT_ID` و `ZARINPAL_SANDBOX` |
| زیبال | `gateways/zibal.ts` | `ZIBAL_MERCHANT` (برای تست: `zibal`) |
| هر درگاه دیگر (بانکی/واسط) | از روی `gateways/_template.ts` | یک خط در `registry.ts` |

**تغییر درگاه بدون تغییر کد:** فقط `.env` را عوض کنید، مثلاً `PAYMENT_GATEWAYS="zarinpal,zibal"` و `PAYMENT_DEFAULT_GATEWAY="zarinpal"`.
اگر چند درگاه فعال باشد، مشتری در صفحهٔ پرداخت انتخاب می‌کند.

**افزودن درگاه جدید:**
1. `_template.ts` را کپی کنید (مثلاً `sep.ts`) و سه متد `request`، `parseCallback` و `verify` را طبق مستندات درگاه کامل کنید.
2. یک خط به `GATEWAY_FACTORIES` در `registry.ts` اضافه کنید.
3. کلیدها را در `.env` بگذارید. آدرس بازگشت به‌طور خودکار `/api/payments/callback/{id}` است (GET و POST هر دو پشتیبانی می‌شوند).

**ایمنی پرداخت:** مبلغ verify همیشه از پایگاه داده خوانده می‌شود، بازگشت تکراری فقط یک بار پردازش می‌شود، و تکمیل سفارش به‌صورت اتمی انجام می‌شود.

## تنظیمات سطح‌بندی — قابل تغییر بدون برنامه‌نویسی

همهٔ اعداد (تعداد سطح‌ها، نام، آیکون، درصد تخفیف، حد خرید، نیاز به مدرک، ارسال رایگان، پله‌های تعداد، هزینهٔ ارسال، بازهٔ ارزیابی و تنزل خودکار) از یکی از این دو جا خوانده می‌شوند:
- **با پایگاه داده:** جداول `PartnerTier`، `QuantityBreak` و `Setting`
- **بدون پایگاه داده:** فایل `config/commerce.json`

ویرایش از پنل: `ADMIN_TOKEN` را در `.env` بگذارید و به `/admin/settings` بروید. قبل از ذخیره همه‌چیز اعتبارسنجی می‌شود (مثلاً حد خرید سطح بالاتر باید بیشتر باشد). سطح حذف‌شده فقط غیرفعال می‌شود تا همکاران فعلی آسیب نبینند.

> روی سرورهایی که فایل‌سیستم فقط‌خواندنی دارند (مثل Vercel)، ذخیره از پنل فقط با پایگاه داده کار می‌کند.

## تست‌ها

`npm test` — ۸۳ تست: موتور قیمت، تنظیمات، درگاه‌ها، سفارش و پرداخت، ورود با کد، نشست، پیامک، پیشرفت سطح، گردش وضعیت سفارش، تأیید همکار، فرم محصول، پیامک اطلاع‌رسانی یکپارچگی کاتالوگ، تنوع محصول (رنگ/فرم)، اعتبارسنجی و ذخیره‌سازی عکس، مدارک همکاران، و فاکتور (تاریخ شمسی، عدد به حروف، ارزش افزوده).

## قوانین همکاری (مقادیر پیش‌فرض)

| سطح | تخفیف | شرط رسیدن (خرید ۱۸۰ روز اخیر) | مدرک لازم |
|---|---|---|---|
| برنزی | ۸٪ | سطح ورود هر همکار تأییدشده | ندارد |
| نقره‌ای | ۱۲٪ | ۱۵۰ میلیون تومان | ندارد |

- تأیید همکار: `NONE` ← `BASIC` (تماس کارشناس + تأیید هویت و محل کار، بدون پروانه) ← `DOCUMENTS`
- ارتقای سطح خودکار است؛ تنزل خودکار فقط اگر در تنظیمات روشن شود. مدیر می‌تواند سطح را قفل کند.
- هر محصول می‌تواند سقف تخفیف، کف قیمت، حداقل تعداد همکار و قیمت دستی برای هر سطح داشته باشد.
